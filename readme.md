# Mini NPU Simulator



## 1. 프로젝트 소개

Python으로 구현한 Mini NPU 시뮬레이터입니다. 입력 패턴과 필터를 비교하여 MAC 연산을 수행하고, 연산 결과와 실행 시간을 분석합니다.



## 2. 주요 기능

- 사용자 입력 모드: 3×3 필터와 패턴을 직접 입력하여 분석

- JSON 분석 모드: data.json에 저장된 여러 패턴 분석

- Cross와 X 필터의 MAC 점수 계산

- 점수 비교를 통한 Cross, X, UNDECIDED 판정

- 기대 정답과 비교하여 PASS/FAIL 출력

- 3×3, 5×5, 13×13, 25×25 크기별 MAC 성능 비교

- 잘못된 입력 및 JSON 데이터 오류 처리



## 3. 실행 방법

Python이 설치된 환경에서 프로젝트 폴더로 이동한 뒤 실행합니다.



```cmd

python main.py

```



실행 후 1번 또는 2번 모드를 선택합니다.



## 4. MAC 연산이란?

MAC(Multiply-Accumulate)은 두 숫자를 곱하고 그 결과를 계속 더하는 연산입니다.



이 프로그램에서는 입력 패턴과 필터에서 같은 위치에 있는 숫자끼리 곱한 뒤 모두 더하여 점수를 계산합니다.



## 5. 판정 방법

- Cross 점수가 높으면 Cross

- X 점수가 높으면 X

- 두 점수 차이가 매우 작으면 UNDECIDED



부동소수점 오차를 고려하여 epsilon(1e-9)을 사용했습니다.



## 6. 결과 리포트

### 6.1 JSON 분석 결과

- 전체 테스트: 6개
- PASS: 3개
- FAIL: 3개
- 실패 패턴: size_5_1, size_13_2, size_25_1

### 6.2 실패 원인 분석

이번 분석에서는 6개 패턴 중 3개가 PASS, 3개가 FAIL로 나타났다.

**1. size_5_1**
- 기대 정답: X
- Cross 점수: 0.9
- X 점수: 0.8999999999999999
- 실패 원인: 두 점수의 차이가 epsilon(1e-9)보다 작아 UNDECIDED로 판정되었다.

**2. size_13_2**
- 기대 정답: Cross
- Cross 점수: 7.499999999999997
- X 점수: 7.5
- 실패 원인: 두 점수가 거의 같아 UNDECIDED로 판정되었다.

**3. size_25_1**
- 기대 정답: X
- Cross 점수: 4.9
- X 점수: 4.899999999999999
- 실패 원인: 두 점수의 차이가 매우 작아 UNDECIDED로 판정되었다.

이번 FAIL은 프로그램이 중단되는 오류가 아니라, 기대 정답과 실제 판정 결과가 일치하지 않은 경우다.

부동소수점은 소수 값을 정확하게 표현하지 못하는 경우가 있어 계산 결과에 미세한 오차가 발생할 수 있다.

따라서 epsilon을 적용하여 점수 차이가 매우 작을 때는 어느 필터가 더 적합한지 결정하지 않고 UNDECIDED로 처리했다.

또한 JSON 데이터의 expected 값인 '+'와 'x'를 각각 Cross와 X로 정규화하여 비교했다.

행렬 크기나 데이터 형식이 잘못된 경우에는 해당 패턴을 FAIL로 기록하고 다음 패턴의 분석을 계속하도록 개선했다.

### 라벨 정규화 함수

normalize_label() 함수는 JSON 데이터의 기대 정답을
프로그램에서 사용하는 표준 라벨로 변환한다.

'+'와 'cross'는 'Cross'로,
'x'와 'X'는 'X'로 변환한다.

기존 조건문을 별도 함수로 분리하여 코드의 중복을 줄이고,
새로운 라벨을 추가하거나 정규화 규칙을 테스트할 때
수정과 검증이 쉽도록 개선하였다.

### 6.3 성능 분석

MAC 연산은 입력 패턴과 필터의 같은 위치에 있는 숫자를 곱한 뒤 모두 더하는 방식이다.

각 크기별로 MAC 연산을 10회 반복하여 평균 시간을 측정했다.

| 크기 | 곱셈 횟수 | 평균 실행 시간(ms) |
|---|---:|---:|
| 3×3 | 9 | 0.002210 |
| 5×5 | 25 | 0.003740 |
| 13×13 | 169 | 0.020570 |
| 25×25 | 625 | 0.070520 |

### 6.4 시간 복잡도 분석

N×N 행렬의 MAC 연산에서는 N²번의 곱셈과 결과를 누적하는 덧셈이 필요하다.

따라서 행렬의 한 변의 길이가 증가할수록 연산 횟수는 제곱에 비례하여 증가한다.

3×3 행렬은 9번의 곱셈이 필요하지만, 25×25 행렬은 625번의 곱셈이 필요하다.

실제 측정에서도 행렬 크기가 커질수록 평균 연산 시간이 증가하는 경향을 확인했다.

이러한 이유로 MAC 연산의 시간 복잡도는 O(N²)이라고 설명할 수 있다.

단, 실제 실행 시간은 컴퓨터의 성능이나 실행 환경에 따라 달라질 수 있다.

이번 미션을 통해 AI의 기본 연산인 MAC의 원리와 입력 데이터 검증, 부동소수점 비교 정책, 연산량 증가에 따른 성능 변화를 이해할 수 있었다.

### 모드별 동점 처리 규칙 비교

모드 1(사용자 입력 모드)과 모드 2(JSON 분석 모드)는
두 MAC 점수의 차이가 epsilon(1e-9)보다 작으면
동점으로 판단하여 UNDECIDED를 출력한다.

모드 1에서는 사용자가 입력한 필터 A와 B의 점수를 비교한다.
동점이 아니면 점수가 높은 필터를 A 또는 B로 판정하며,
동점이면 UNDECIDED를 출력하고 분석을 마친다.
별도의 PASS/FAIL 검증은 수행하지 않는다.

모드 2에서는 JSON 데이터의 Cross와 X 필터 점수를 비교한다.
동점이면 UNDECIDED로 판정하며,
기대 정답인 Cross 또는 X와 일치하지 않으므로
FAIL로 집계한다.

따라서 두 모드의 동점 판단 기준은 같지만,
모드 1은 판정 결과만 출력하고
모드 2는 기대 정답과 비교하여 검증 결과까지 집계한다.

### 대형 행렬 처리의 한계와 최적화 방안

현재 Mini NPU Simulator는 Python 반복문을 사용하여
행렬의 각 원소를 곱하고 누적하는 MAC 연산을 수행한다.

1. 대형 행렬의 시간 문제

N×N 행렬의 MAC 연산에는 N²번의 곱셈이 필요하다.

3×3 행렬은 9번,
25×25 행렬은 625번,
1000×1000 행렬은 1,000,000번의 곱셈이 필요하다.

따라서 행렬 크기가 커질수록 연산 시간이 증가하며,
시간 복잡도는 O(N²)이다.

2. 메모리 사용 문제

1000×1000 행렬은 100만 개의 원소를 저장해야 한다.

입력 행렬과 필터 행렬을 각각 저장해야 하므로
메모리 사용량도 증가한다.

Python 리스트는 원소별 객체 참조 등의 추가 비용이 있어
실제 메모리 사용량은 원소의 숫자 데이터 크기보다 클 수 있다.

3. 최적화 방안

첫째, 블록 단위 처리
큰 행렬을 작은 블록으로 나누어 순차적으로 처리하면
전체 데이터를 한꺼번에 메모리에 올리지 않는
방식으로 확장할 수 있다.

둘째, 데이터 복사 최소화
불필요한 행렬 복사를 줄여 메모리 사용량과
데이터 이동에 따른 비용을 줄인다.

셋째, 배열 연산 활용
향후 NumPy와 같은 라이브러리를 활용하면
Python 반복문보다 효율적으로 계산할 수 있다.

넷째, 병렬 처리
독립적인 곱셈 연산을 병렬로 수행할 수 있는
하드웨어를 활용하면 연산 시간을 단축할 가능성이 있다.

4. 향후 개선 방향

현재 프로그램은 교육용 시뮬레이터이므로
실제 NPU 하드웨어를 사용하지 않는다.

향후 대형 행렬을 처리할 경우 블록 처리,
메모리 접근 최적화, 병렬 연산을 우선 검토할 계획이다.

### CPU와 NPU의 연산 방식 및 병목 비교

1. CPU의 특징

CPU는 다양한 종류의 명령어를 처리하는 범용 프로세서이다.

현재 Mini NPU Simulator는 Python으로 작성되어
일반 CPU에서 MAC 연산을 수행한다.

Python 반복문을 사용하여 행렬의 원소를 순서대로
곱하고 누적하므로 행렬 크기가 증가할수록
연산 시간이 길어진다.

CPU도 여러 코어와 SIMD 명령어를 통해 병렬 연산이
가능하지만, 현재 프로그램은 이러한 기능을
직접 활용하도록 최적화되어 있지 않다.

2. NPU의 특징

NPU(Neural Processing Unit)는 인공지능 연산에
특화된 프로세서이다.

신경망에서 반복적으로 수행되는 곱셈과 누적 연산을
다수의 연산 장치에서 병렬로 처리하도록 설계되어 있다.

따라서 대규모 행렬 연산에서 일반적인 Python 반복문
기반 처리보다 높은 처리량을 기대할 수 있다.

3. CPU와 NPU의 병목 현상

CPU에서는 반복문 실행 비용, 명령어 처리 비용,
메모리 접근 등이 성능에 영향을 준다.

NPU에서는 많은 연산을 동시에 처리할 수 있지만,
필요한 데이터를 충분히 빠르게 공급하지 못하면
연산 장치가 대기하는 메모리 대역폭 병목이 발생한다.

또한 작은 행렬에서는 데이터 전송이나 초기화 비용이
실제 연산 시간보다 커질 수 있다.

4. 개선 방향

CPU에서는 배열 연산 활용, 반복문 최적화,
불필요한 메모리 접근 감소 등을 고려할 수 있다.

NPU에서는 데이터 재사용, 블록 단위 처리,
메모리 이동 최소화 등을 통해 효율을 높일 수 있다.

현재 프로젝트는 실제 NPU의 처리 속도를 측정한 것이
아니라 MAC 연산의 원리를 Python으로 구현한
교육용 시뮬레이터이다.

따라서 본 프로젝트의 실행 시간은 CPU 기반
Python 프로그램의 측정 결과이며,
실제 CPU와 NPU의 성능 비교 실험 결과는 아니다.
