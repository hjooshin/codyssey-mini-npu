# Mini NPU Simulator

> Python으로 MAC 연산을 구현하고, 숫자 패턴을 비교하며 AI 연산의 기본 원리를 학습하는 교육용 프로젝트

## 1. 프로젝트 소개

Mini NPU Simulator는 입력 패턴과 필터의 숫자를 비교하여 **MAC(Multiply-Accumulate, 곱셈 누적 연산)** 점수를 계산하는 Python 프로그램입니다. 점수를 이용해 패턴을 판정하고, 데이터 크기에 따라 연산 시간이 어떻게 달라지는지 분석합니다.

**실제 NPU 하드웨어를 구동하는 프로그램은 아닙니다.** 일반 CPU에서 Python으로 NPU에 사용되는 기본 연산 원리를 실습합니다.

### 1.1 프로젝트 목표

1. MAC 연산을 Python으로 구현하기
2. 두 필터의 점수를 비교하여 패턴 판정하기
3. JSON 파일에 있는 여러 패턴 자동 분석하기
4. 잘못된 입력과 데이터 오류 처리하기
5. 행렬 크기별 연산 시간과 시간 복잡도 이해하기

## 3. 실행 방법

프로젝트 폴더에서 다음 명령어를 실행합니다.

```bash
python main.py
```

실행 후 메뉴에서 모드를 선택합니다.

### 3.1 모드 1: 사용자 입력

사용자가 **3×3 필터 A, 필터 B, 입력 패턴**을 직접 입력합니다. 프로그램은 두 필터의 MAC 점수를 계산하고 `A`, `B`, `UNDECIDED` 중 하나로 판정합니다.

### 3.2 모드 2: JSON 자동 분석

`data.json`의 **5×5, 13×13, 25×25** 패턴을 분석합니다. Cross(십자가)와 X 필터의 점수를 비교하고, 기대 정답과 일치하는지 `PASS` 또는 `FAIL`로 표시합니다. 크기별 실행 시간도 측정합니다.

## 4. MAC 연산 이해하기

### 4.1 MAC이란?

MAC은 **같은 위치의 숫자끼리 곱한 뒤, 그 결과를 모두 더하는 계산**입니다.

예를 들어 입력이 `[1, 0, 1]`, 필터가 `[1, 1, 0]`이라면:

```text
(1 × 1) + (0 × 1) + (1 × 0) = 1
```

MAC 점수는 `1`입니다. 실제 프로그램은 이를 2차원 행렬 전체에 적용합니다.

### 4.2 점수로 패턴 판정하기

- A 또는 Cross의 점수가 더 높으면 해당 필터로 판정합니다.
- B 또는 X의 점수가 더 높으면 해당 필터로 판정합니다.
- 두 점수가 거의 같으면 `UNDECIDED`(판정 보류)로 처리합니다.

여기서 MAC 점수는 **확률이나 백분율이 아닙니다.** 이 프로젝트에서는 동일한 입력에 대한 두 필터의 상대적 점수를 비교합니다.

## 5. 부동소수점 오차와 동점 처리

### 5.1 epsilon을 사용하는 이유

컴퓨터는 일부 소수를 정확히 표현하지 못해 미세한 계산 차이가 생깁니다.

```text
Cross 점수: 0.9
X 점수:     0.8999999999999999
```

이 값들은 사실상 같으므로, 프로그램에서는 **`epsilon = 1e-9`**를 사용합니다. 두 점수의 차이가 이 값보다 작으면 `UNDECIDED`로 판정합니다. epsilon은 이 프로젝트에서 선택한 허용오차로, 모든 데이터에 항상 적합한 값은 아닙니다.

### 5.2 모드별 동점 처리 비교

| 항목 | 모드 1 | 모드 2 |
|---|---|---|
| 비교 대상 | 필터 A와 B | Cross와 X |
| 동점 기준 | 점수 차이 < `1e-9` | 점수 차이 < `1e-9` |
| 동점 결과 | `UNDECIDED` | `UNDECIDED` |
| 기대 정답 비교 | 없음 | 있음 |
| 동점 시 PASS/FAIL | 집계하지 않음 | 기대 정답이 Cross/X라면 `FAIL` |

즉 **동점 기준은 같지만, 모드 2만 기대 정답과 비교해 검증 결과를 집계**합니다.

## 6. JSON 분석과 라벨 정규화

### 6.1 JSON이란?

JSON은 데이터를 일정한 형식으로 저장하는 파일입니다. `data.json`에는 필터, 입력 패턴, 기대 정답이 들어 있습니다.

예를 들어 `size_5_1`은 5×5 크기의 첫 번째 패턴을 나타냅니다.

### 6.2 라벨 정규화 함수

JSON의 기대 정답은 `+`, `x`처럼 기호로 표시될 수 있지만, 프로그램의 판정 결과는 `Cross`, `X`라는 이름을 사용합니다. 이를 통일하는 함수가 **`normalize_label()`**입니다.

| 원래 라벨 | 표준 라벨 |
|---|---|
| `+` | `Cross` |
| `cross`, `Cross` | `Cross` |
| `x`, `X` | `X` |

기존 조건문을 별도 함수로 분리해 **라벨 변환 규칙을 한곳에서 관리**하고, 재사용과 테스트를 쉽게 했습니다.

### 6.3 새로운 라벨을 추가하려면?

예를 들어 Circle(O)을 지원하려면 다음과 같은 변경이 필요합니다.

1. `data.json`에 새 필터와 패턴을 추가합니다.
2. `normalize_label()`에 새 라벨의 변환 규칙을 추가합니다.
3. 새 필터도 점수를 계산하도록 판정 코드를 확장합니다.
4. 정상 입력, 동점, 잘못된 라벨을 테스트합니다.

**현재는 Cross와 X만 지원하며, 새 라벨 추가는 향후 확장 계획입니다.**

## 7. JSON 분석 결과와 실패 원인

### 7.1 분석 결과

| 항목 | 개수 |
|---|---:|
| 전체 테스트 | 6 |
| PASS | 3 |
| FAIL | 3 |

FAIL 패턴: `size_5_1`, `size_13_2`, `size_25_1`

### 7.2 실패 패턴 상세

| 패턴 | 기대 정답 | Cross 점수 | X 점수 | 실제 판정 |
|---|---|---:|---:|---|
| `size_5_1` | X | 0.9 | 0.8999999999999999 | UNDECIDED |
| `size_13_2` | Cross | 7.499999999999997 | 7.5 | UNDECIDED |
| `size_25_1` | X | 4.9 | 4.899999999999999 | UNDECIDED |

세 경우 모두 두 점수의 차이가 epsilon보다 작아 **동점으로 판정**되었습니다. 기대 정답은 Cross 또는 X이므로 `FAIL`로 집계됐습니다.

**중요:** 여기서 FAIL은 프로그램이 중단된 오류가 아니라, **실제 판정이 기대 정답과 일치하지 않았다는 검증 결과**입니다.

## 8. 행렬 크기별 성능 분석

### 8.1 실행 시간 측정

MAC 연산을 각 크기에서 10회 반복하고 평균 실행 시간을 기록했습니다.

| 행렬 크기 | 곱셈 횟수 | 평균 실행 시간(ms) |
|---|---:|---:|
| 3×3 | 9 | 0.002210 |
| 5×5 | 25 | 0.003740 |
| 13×13 | 169 | 0.020570 |
| 25×25 | 625 | 0.070520 |

*위 수치는 기존 실습 기록의 한 측정 결과입니다. 실행 환경에 따라 달라질 수 있습니다.*

### 8.2 시간 복잡도 O(N²)

N×N 행렬은 N²개의 원소를 계산합니다. 예를 들어 3×3은 9번, 25×25는 625번 곱합니다. 따라서 MAC 계산의 **시간 복잡도는 O(N²)**입니다.

쉽게 말해 **가로와 세로 길이가 각각 2배가 되면 계산할 원소 수는 4배**가 됩니다.

## 9. 1000×1000 대형 행렬의 한계

### 9.1 예상 문제

- **시간:** 1000×1000 행렬은 100만 개의 원소를 계산해야 하므로 연산 시간이 증가합니다.
- **메모리:** 입력 행렬과 필터를 저장해야 하며, Python 리스트에는 숫자 자체 외에도 추가 저장 비용이 발생합니다.

### 9.2 개선 방안

1. **블록 처리:** 큰 행렬을 작은 단위로 나누어 계산합니다. 데이터를 블록별로 읽는 방식과 결합하면 메모리 부담을 줄일 수 있습니다.
2. **복사 최소화:** 불필요한 데이터 복사를 줄입니다.
3. **배열 연산:** 향후 NumPy 등의 도구로 반복문 계산을 최적화할 수 있습니다.
4. **병렬 처리:** 여러 연산 장치를 활용해 독립적인 계산을 동시에 수행할 수 있습니다.

위 항목은 **향후 개선 방향**이며, 현재 프로그램에 모두 구현된 기능은 아닙니다.

## 10. CPU와 NPU 비교

### 10.1 CPU와 NPU는 어떻게 다른가?

| 구분 | CPU | NPU |
|---|---|---|
| 역할 | 여러 종류의 작업 처리 | AI 계산에 특화 |
| 특징 | 범용성 | 많은 곱셈·덧셈을 병렬 처리하도록 설계 |
| 성능에 영향을 주는 요소 | 반복문·명령어 처리·메모리 접근 등 | 데이터 공급 속도·메모리 대역폭 등 |

CPU도 여러 코어와 SIMD 기능으로 병렬 연산을 수행할 수 있지만, **현재 Python 코드는 이를 직접 활용하도록 최적화하지 않았습니다.**

### 10.2 병목 현상이란?

**병목**은 전체 처리 과정에서 특정 단계가 느려져 성능을 제한하는 현상입니다.

- CPU 기반 Python 프로그램에서는 반복문 처리와 메모리 접근 등이 성능에 영향을 줍니다.
- NPU에서는 연산 장치가 빨라도 필요한 데이터를 제때 공급하지 못하면 대기 시간이 발생합니다. 이를 **메모리 대역폭 병목**이라고 합니다.
- 작은 연산에서는 데이터를 옮기거나 장치를 준비하는 비용이 계산 자체보다 클 수도 있습니다.

이번 프로젝트의 실행 시간은 **CPU에서 실행한 Python 프로그램의 측정 결과**이며, 실제 NPU와 성능을 비교한 실험 결과가 아닙니다.
